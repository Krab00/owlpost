## Description
Finding from 2026-09-06 (fourth recurrence of "the watch was not armed": OWL-023, b9fd1e6,
8ecd3b3, OWL-026). Two root causes, neither closed by the earlier fixes:

1. **The fixes never reached the machine.** `owl update --source <dir>` runs
   `cargo install --path`, which writes `~/.cargo/bin/owl`, while the release installer
   (`scripts/install.sh`) put `owl` in `~/.local/bin`; PATH and the systemd unit
   (`ExecStart=/home/kris/.local/bin/owl`) resolve that copy. After every `owl update` the old
   binary stayed active and the hook kept printing the old sentence, although `cargo test` on
   the checkout was green. Observed today: `~/.cargo/bin/owl` 14:22 (new), `~/.local/bin/owl`
   00:04 (old), hook output = old pointer sentence.
2. **One skipped turn loses the watch for the whole session.** The arm sentence is injected once
   (`SessionStart`); when the model treats it as ambient context (it did again today, first
   turn `/owlpost:ask`), nothing ever asks again. A hook cannot see whether a Monitor runs —
   but the Monitor's own process can leave a marker the hook can see.

Fix (three parts; the design doc §9 and §11 are updated in the same PR, and where this file
and the design doc disagree the design doc wins and this file is corrected):

### A. `owl update` replaces the binary that is actually running
- `run_update` computes `active = install::owl_path()` (canonicalised `current_exe`) before
  anything else. `--source <dir>` builds with `cargo install --path <dir> --locked --root <tmp>`
  (so nothing lands in `~/.cargo/bin`), then replaces `active` with `<tmp>/bin/owl` by
  temp-file + `rename` in the same directory (a plain copy fails with `ETXTBSY` while the
  daemon runs the file; rename does not). Without `--source` the release installer is run with
  `--prefix <dir of active>` so it, too, replaces the active copy. After the replacement the
  command verifies that `active` is byte-identical to the built file (sha256 or a full read
  compare) and prints `installed <active>`; a mismatch is a hard error naming both paths.
  `--dry-run` prints `would replace <active>`. The unit reinstall stays as is (it already
  points at `owl_path()`).
- `owl doctor` gains a `binary` check: `ok binary: <path>` when the `owl` that PATH resolves
  (first `owl` in `$PATH`, canonicalised) is the same file as `current_exe` and the daemon unit
  (if installed) names that path; `warn binary: PATH resolves <p>, this owl is <q>` /
  `warn binary: daemon unit runs <r>` otherwise, never `fail`. The PATH lookup is a small
  function that takes the `PATH` string and is unit-tested with a temp dir.

### B. Per-session re-arm until the watch is live
- New `owl inbox --count --follow --session <id>` (plain format only): on start writes a marker
  `$OWLPOST_HOME/watch/<session id>` containing its own pid, then loops: every 5 s runs the
  count, prints the counter sentence (with the owl icon, OWL-027) only when it changed since the
  previous poll, prints nothing at zero (so "back to zero" is silent), never marks anything
  seen; on a clean exit it removes the marker (a killed process leaves it — that is fine, see
  staleness). The session id is validated as `[A-Za-z0-9._-]{1,128}`; anything else is a usage
  error, so the marker path can never escape `watch/`. This replaces the shell one-liner of
  OWL-023/026; `commands/watch.md`, SKILL.md and the design doc quote the new command instead
  and the OWL-026 "one-liner stated twice, pinned byte-identical" rule now applies to the
  command template `owl inbox --count --follow --session <session id>`.
- A marker is **live** when its pid is alive (`/proc/<pid>` on Linux, `kill -0` elsewhere —
  implementer's choice, tested with a spawned `sleep` child and with a pid that cannot exist);
  stale markers are ignored and may be removed by the hook path.
- `owl inbox --count --format claude` reads the hook's stdin JSON when stdin is not a terminal
  (Claude Code sends `{"session_id": "...", "hook_event_name": "...", ...}`; only `session_id`
  is used; unparseable or missing stdin means "no session id"). The arm sentence is emitted
  on `SessionStart` **and** `UserPromptSubmit` (never `PostToolUse`) when the stored default
  is on (`plugin.json`, unchanged semantics) and no live marker exists for that session id.
  Without a session id the sentence is emitted on `SessionStart` only (old behaviour, so a
  harness that sends no stdin keeps working). `--session-start` is removed from `hooks.json`
  and from the CLI (or kept as an ignored no-op with a `// ponytail:` — implementer's call, but
  the tests must not depend on it).
- `ARM_SENTENCE` becomes a template carrying the session id:
  `owlpost: before handling this prompt, arm the inbox watch for this session: call Monitor
  with persistent: true, description "owlpost inbox" and this command (verbatim):
  \`owl inbox --count --follow --session <id>\`. Then handle the prompt.` It must still start
  with `owlpost: before handling this prompt`, stay on one line and keep `--format claude`
  valid JSON.
- `commands/watch.md`: `status` arms (as OWL-026) using the command from **this turn's**
  sentence; when this turn carries no sentence and the default is on, the watch is already
  live — say `owlpost watch: running; default on`. `on` writes `{"watch": true}`, arms from
  this turn's sentence when there is one, otherwise says
  `owlpost watch: on; it arms on your next prompt` (the next `UserPromptSubmit` injects the
  sentence). `off` unchanged (TaskStop + `{"watch": false}`; the marker disappears with the
  process). SKILL.md "Live watch": the sentence may appear on any turn, not only the first;
  whenever it is present, arm — its presence means no watch is live for this session, even if
  one was armed earlier and died.

### C. Proof on the real harness: `scripts/e2e-watch-arm.sh`
A script for humans **and** for this task's verifier. For each first prompt in
`/owlpost:watch status`, `/owlpost:whoami`, `what is 2+2? answer with the number only`:
1. creates a temp `OWLPOST_HOME` (`owl init` there, no daemon needed — `--count` reads the
   spool only);
2. runs `claude -p "<prompt>" --output-format stream-json --verbose --max-turns 6` in the
   background (the persistent Monitor keeps `claude -p` alive, so the run is bounded by
   `timeout 180`), optionally with `--plugin-dir <repo>/plugins/claude-code` and `PATH` led by
   the branch build (`E2E_PLUGIN_DIR`, default: the installed plugin and the `owl` on PATH);
3. takes the session id from the first stream event, waits up to 120 s for
   `$OWLPOST_HOME/watch/<session id>` with a live pid, and asserts the stream holds one
   `tool_use` named `Monitor` whose input has `"description":"owlpost inbox"` and
   `--session <that id>`;
4. kills the run, prints `PASS <prompt>` / `FAIL <prompt> (<reason>)` and exits non-zero on
   any FAIL. The stream files are kept under `E2E_OUT` (default: a temp dir printed at the
   end) as evidence.
The verifier runs it against the task branch build and attaches the output; after the merge
the orchestrator runs `owl update --source .` on this machine and runs it once more against the
installed binary and plugin (AC8). Cost: three `claude -p` calls per run.

Out of scope: Codex/Kimi; OS notifications; anything that makes the hook itself start a
process (hooks must stay pure and fast).
