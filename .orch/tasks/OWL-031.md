## Description
Finding from 2026-09-06 (fifth recurrence of "the watch is not running", after OWL-023/026/029/030):
the user opened a fresh session and saw no watch. Root cause is structural, not a bug: the watch is a
`Monitor` the **model** arms, and Claude Code never runs a model turn on `SessionStart` — the hook can only
inject text, so nothing happens until the first prompt. Two more costs of that design: the `--follow` loop
polls every 5 s, and its pid markers under `$OWLPOST_HOME/watch/` go stale when a session ends or `TaskStop`
kills the follow (three dead markers on the dev machine today; the hook only sweeps the current session id).

Replacement, proven on claude 2.1.263 in both `claude -p --input-format stream-json` and a real interactive
REPL driven through a pty (fixtures: session scratchpad `fcw/{settings.json,session-start.sh,file-changed.sh,pty_test.py}`):

1. A `SessionStart` hook's JSON may carry `hookSpecificOutput.watchPaths: ["<absolute path>"]` (in the
   binary: "Absolute paths to watch for FileChanged hooks"; not in the docs). Claude Code watches those
   paths with chokidar (`ignoreInitial: true`, `awaitWriteFinish` 500 ms); directories work and yield
   `add` / `change` / `unlink`.
2. A `FileChanged` command hook with `"asyncRewake": true` receives
   `{session_id, transcript_path, cwd, hook_event_name: "FileChanged", file_path, event}` on stdin. When it
   exits **2**, Claude Code wakes the idle session with a new model turn and shows the hook's stderr (stdout
   if stderr is empty) as a system reminder; any other exit code is silent. The interactive session woke in
   the same second the file was added. `async`/`asyncRewake` are ignored on `SessionStart`, `Stop` and
   `UserPromptSubmit` (documented), so the chain must go through `FileChanged`.
3. The wake runs the `UserPromptSubmit` hooks too, and the TUI labels it "Stop hook feedback" (the binary
   has `@internal` `rewakeMessage`/`rewakeSummary`; not part of this task).

So the plugin stops asking the model to arm anything. The hook registers the spool inbox directory on
session start and a second hook wakes the session when a record is added. The design doc §9, §11 and §12
are updated in the same PR; where this file and the design doc disagree, the design doc wins and this file
is corrected.

### A. `owl inbox --count --format claude` — SessionStart registers the watch
- `--hook-event SessionStart` **always** prints one JSON line (also at count 0) whose `hookSpecificOutput`
  carries `hookEventName: "SessionStart"`, `watchPaths: ["<home>/spool/inbox"]` (absolute; `<home>` is the
  resolved `$OWLPOST_HOME`, canonicalised when it exists) and `additionalContext` only when there is text
  (counter sentence + previews + `OPEN_SENTENCE` as today; the key is omitted when empty). When
  `plugin.json` says `{"watch": false}` there is no `watchPaths` key, and at count 0 nothing is printed
  (today's behaviour).
- The arm sentence (`ARM_PREFIX`, `arm_sentence`, `WATCH_COMMAND`'s role as a template) is removed from the
  Claude injection on every event; `UserPromptSubmit` and `PostToolUse` keep today's shape (counter only,
  nothing at 0). The live-marker check in the hook path goes away with it.
- `--hook-event SessionStart` sweeps `$OWLPOST_HOME/watch/`: every marker whose pid is dead is removed
  (all of them, not only the current session's). The sweep never fails the hook.

### B. `--hook-event FileChanged` — the wake
- Reads the hook stdin JSON (same reader as today; a terminal, empty or unparseable stdin, or a missing
  `event` → exit 0, print nothing). Never marks anything seen.
- `event == "add"` and unseen count > 0 and the watch is enabled (`plugin.json` not `{"watch": false}`)
  → prints the counter sentence (`sentence()`, 🦉 icon, same text as `--follow`) to **stderr** and exits
  **2**. Everything else (`change`, `unlink`, count 0, watch off) → exit 0, nothing printed.
  Design note: keying on `add` is the de-duplication — marking seen and moving to `done/` are `change`/
  `unlink`, so they never wake; two records arriving in a burst wake twice, which is acceptable.
- `--format claude` is required (the other formats have no such hook; `--hook-event FileChanged` with
  another format is a usage error, exit 2 from clap — distinct from the wake's exit 2 by its stderr text).

### C. Plugin files
- `hooks.json`: add
  `"FileChanged": [{"hooks": [{"type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/hooks/owl-count.sh --hook-event FileChanged", "asyncRewake": true, "timeout": 5}]}]`
  (the `${CLAUDE_PLUGIN_ROOT}` placeholder stays literal in the file). `SessionStart`, `UserPromptSubmit`,
  `PostToolUse` entries unchanged. `owl-count.sh` unchanged (it already passes `"$@"` and stdin through and
  is a strict no-op on failure) — but note its `2>/dev/null`: the wake's sentence goes to stderr, so the
  script must let stderr through on `FileChanged` (or the sentence goes to stdout there and the hook
  falls back to stdout — implementer's choice; the test pins whichever is chosen through the real script).
- `commands/watch.md`: `on` writes `{"watch": true}` and says
  `owlpost watch: on; the inbox is watched from the next session start`; `off` writes `{"watch": false}`
  and says `owlpost watch: off; this session stops waking now, new sessions do not watch`; `status` reads
  `plugin.json` and says `owlpost watch: default on|off; event-driven (FileChanged), nothing to arm`. No
  `Monitor`, `TaskStop`, marker or "arms on your next prompt" anywhere in the file. `allowed-tools` drops
  `Monitor` and `TaskStop`.
- `skills/owlpost/SKILL.md` "Live watch": one paragraph — the hook wakes the session with the counter
  sentence when a record arrives; report it in one line and offer `/owlpost:inbox`; nothing to arm; no
  sentence starting `owlpost: before handling this prompt` exists any more. README row for
  `/owlpost:watch` rewritten accordingly.
- `docs/technical-design.md` §9 (hook injection bullets + the `owl inbox` row), §11 and §12: describe
  `watchPaths` + `FileChanged` + `asyncRewake` + exit 2, the `add`-only rule, the dead-marker sweep; the
  marker/per-turn re-arm description and `scripts/e2e-watch-arm.sh` rows are replaced.

### D. What stays
- `owl inbox --count --follow [--session <id>]` stays as is (a poll loop any harness can run; the marker
  it writes is now only informational) — one `// ponytail:` line names it as the fallback for hosts
  without `FileChanged`. Nothing in the Claude plugin references it any more.

### E. Proof on the real harness: `scripts/e2e-watch-wake.sh` (replaces `e2e-watch-arm.sh`)
1. temp `OWLPOST_HOME` (`owl init`, no daemon), `owl` from `PATH` (led by the branch build by the
   verifier), `E2E_PLUGIN_DIR` → `--plugin-dir` (default: installed plugin);
2. `claude -p --input-format stream-json --output-format stream-json --verbose --include-hook-events
   --permission-mode bypassPermissions` in the background with stdin held open: sends one user message
   (`Reply with exactly the word: ready`), waits for the `result` event, then drops one unseen question
   record into `$OWLPOST_HOME/spool/inbox/` (a fixture built the way `tests/inbox.rs` builds records);
3. within 60 s asserts a second `assistant` event appears with **no** second user message sent, and that a
   `system` `hook_response` for `FileChanged` with `exit_code: 2` and the 🦉 sentence precedes it;
4. prints `PASS`/`FAIL <reason>`, keeps the stream under `E2E_OUT`, exits non-zero on FAIL, bounded by
   `timeout 180`. Cost: one `claude -p` call.
The interactive (pty) proof stays manual (AC8, orchestrator, post-merge).

Out of scope: `rewakeMessage`/`rewakeSummary`; Codex/Kimi; OS notifications; watching anything but
`spool/inbox`.
