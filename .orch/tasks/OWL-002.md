## Description
Implement `identity.rs` per `docs/technical-design.md §4`: generate an ed25519 keypair, store the
32-byte seed at `$OWLPOST_HOME/key` with mode 0600, load it, derive the `ed25519:<base64>` public
key encoding and the `owl:<16 base32 chars>` fingerprint, and expose `sign(&[u8]) -> Signature`
and `verify(pubkey, &[u8], sig) -> bool`. `owl init` creates the home, key and config
(`--name`, `--email` repeatable) and prints the fingerprint; it refuses to overwrite an existing
key. `owl whoami` prints fingerprint, pubkey, name, endpoints (text and `--json`).

## Acceptance criteria
- [ ] AC1: `owl --home <tmp> init --name Test --email t@example.org` exits 0, creates `key` with mode 0600 (unix) and `config.json` with the name/email, and prints a line matching `^owl:[a-z2-7]{16}$` (modality: test)
- [ ] AC2: running `owl init` again on the same home exits 1 with a message containing `already exists` and leaves `key` byte-identical (modality: test)
- [ ] AC3: unit test `identity::tests::fingerprint_is_stable` asserts the fingerprint of a fixed seed equals a hard-coded expected value and has length 20 (`owl:` + 16) (modality: test)
- [ ] AC4: unit test `identity::tests::sign_verify_roundtrip` verifies a signature over arbitrary bytes and rejects it after flipping one byte of the message and after flipping one byte of the signature (modality: test)
- [ ] AC5: unit test `identity::tests::pubkey_encoding_roundtrip` parses `ed25519:<base64>` back to the same key and rejects a wrong prefix (modality: test)
- [ ] AC6: `owl --home <tmp> whoami --json` prints JSON with keys `fingerprint`, `pubkey`, `name`, `endpoints` (modality: test)
