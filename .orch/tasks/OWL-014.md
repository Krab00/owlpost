## Description
Write `tests/e2e.rs` per `docs/technical-design.md §12`: two daemons A and B from
`tests/common` (temp homes, port 0, a fixture repo with both peer files, B's `projects` mapping
the fixture repo, fake harness, `OWLPOST_NOTIFY_CMD` logging script, `pull_interval_secs = 1`).
Scenario `manual_loop`: A asks → B holds for consent → B `owl allow --once` → B `owl inbox`
shows it → B `owl draft` → B `owl send` → A's daemon pulls → A `owl inbox --count --format
claude` shows 1 → A `owl show` prints the answer with `[redacted]` → A's cache hit on re-ask
with B stopped. Scenario `auto_loop`: policy auto → answer arrives without any B command.
Scenario `security`: a third identity C not in B's book is refused at handshake; a replayed
question envelope is rejected with 409; the 21st question in an hour is 429. Write
`scripts/e2e-real.sh`: same manual loop against a real harness chosen by `OWL_HARNESS`
(`claude|codex|opencode`), using two temp homes on this machine, a small throwaway git repo as
the project, printing each step and the final answer, saving logs under `target/e2e-real/`.
It is not run by CI. Document how to run it in `docs/technical-design.md §12`.

## Notes
- Flaky on macOS CI (PR #9 run 33741787430): `tests/doctor.rs::doctor_reports_each_check` asserts the exact
  string `last pull 11s ago`; a slow runner produced `12s`. Loosen the assertion (tolerate a range or
  inject the clock) as part of this task so AC6 (green on macOS and Linux) is stable.
