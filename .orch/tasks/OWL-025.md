## Description
Follow-up to OWL-024, from the manual smoke on 2026-09-05 (AC9 of OWL-024). Findings:

- A server bundled through the plugin's `.mcp.json` is named `plugin:owlpost:owl` by Claude
  Code, so the mention reads `@plugin:owlpost:owl:to://…` and the 16-character prefix sinks
  the resource in the `@` typeahead ranking: `@krz` never showed it, `@owl` ranked it third.
- The same server registered at user scope (`claude mcp add --scope user owl -- owl mcp`)
  is named `owl`: `@owl:krz` ranks the contact near the top, `@owl:` alone lists the book.
  That is the accepted UX: type `@owl:` and the start of the name (or e-mail/domain), pick
  with the arrows, type the question. `@krz` alone will never beat files/connectors — that
  ranking is Claude Code's.

Changes (all on the OWL-024 branch `task/OWL-024-mcp-contacts`, so PR #30 updates):

- **Remove `plugins/claude-code/.mcp.json`.** The plugin no longer bundles the server.
- **`owl setup`** (after the plugin steps, only when `claude` is on PATH): if
  `claude mcp get owl` fails, run `claude mcp add --scope user owl -- owl mcp`; if it
  succeeds print `mcp server owl already registered`. `--dry-run` prints
  `would run: claude mcp add --scope user owl -- owl mcp` (or the already-registered line).
- **`owl update`**: the same idempotent registration step, after its plugin steps, same
  dry-run wording.
- **`owl doctor`**: a new check `mcp` after the harness checks: `ok` when
  `claude mcp get owl` exits 0 (`owl registered in Claude Code (user scope)`); `warn` when
  `claude` is on PATH but the server is missing, detail ending with the fix
  `claude mcp add --scope user owl -- owl mcp`; `warn` `claude not on PATH` otherwise. Never
  `fail` (owlpost works without Claude Code).
- **Docs**: `commands/contacts.md` hint becomes the single line
  `Type @owl: and the start of the name, pick the contact, then type the question.`
  (keep `@owl:to://` as the shape of the inserted mention); README "Mention a contact"
  rewritten: `@owl:krz` example, registration by `owl setup`/`owl update` (or the
  `claude mcp add` line by hand), `owl doctor` check, no `.mcp.json`; the README components
  table row "MCP server" points at `owl mcp` + `owl setup`; SKILL.md "Mentioned contact"
  gains the `@owl:` typing hint and drops the `.mcp.json` note; design doc §9 `owl mcp` row
  and §11 (service install / setup) mention the user-scope registration and the doctor check.
- Tests use a fake `claude` script on PATH that logs argv (as the plugin steps are tested);
  `claude mcp get owl` exit status is scripted per case.

Out of scope: changing the URI shape, re-ranking inside Claude Code, Codex/Kimi.
