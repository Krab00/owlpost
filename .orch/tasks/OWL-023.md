## Description
Finding from the second cross-machine exchange (2026-09-05): the answer from the peer landed
in the daemon at 23:11:47 and the OS notification fired, but nothing appeared in the open
Claude Code session until the user ran `/owlpost:inbox` by hand. The hooks (`SessionStart`,
`UserPromptSubmit`, `PostToolUse`) only inject when the user or Claude already acts; an
idle session has no event to attach to. Users expect the answer to show up in the
conversation on its own, from the moment the plugin is installed.

Claude Code has a channel for this: the `Monitor` tool runs a background script whose every
stdout line becomes a notification in the session, even while idle. Make the plugin use it:

- **Automatic from install.** On `SessionStart` the hook injects, besides the counter, a
  one-line instruction to arm the owlpost watch (once per session, `persistent: true`) unless
  the watch is switched off (see below). The skill tells Claude to arm it silently on the first
  turn and never mention it again. The watch script polls `owl inbox --count --format plain`
  every few seconds and emits the line only when it changes, so one event per new
  question/answer batch, none while quiet; it never lists or shows records (listing marks
  seen).
- **When an event lands**, Claude says one line ("owlpost: 1 new answer from Maciek") and
  offers the `/owlpost:inbox` flow; nothing is opened, drafted or sent on its own (ground
  rule from the skill).
- **`/owlpost:watch on|off|status`.** `off` stops the running Monitor (TaskStop) and writes
  the choice to `$OWLPOST_HOME/plugin.json` (`{"watch": false}`) so later sessions do not arm
  it; `on` re-arms it and writes `true`; `status` says whether a watch is running and what
  the stored default is. The hook reads the same file (`owl inbox --count --format claude`
  gains the instruction only when `watch != false`). Default when the file is absent: on.
- **Codex / Kimi**: the injected instruction is Claude-specific; other `--format` values keep
  today's output (no Monitor there).

Implementation sketch: `owl inbox --count --format claude` prints, when the watch is enabled
and the session-start flag is passed (`--session-start`, set by `hooks.json` for the
`SessionStart` matcher only), a second `additionalContext` sentence:
"owlpost: arm the inbox watch (see /owlpost:watch)". `commands/watch.md` holds the script and
the on/off/status handling; `skills/owlpost/SKILL.md` gains a "Live watch" section (arm once,
silent, one-line report per event, never act on its own). `docs/technical-design.md` §9
documents the flag, the file and the sentence.

Out of scope: push notifications to the phone (`PushNotification` may be offered by Claude
when an event lands, not required), watching from `owl` itself (the daemon already notifies
the OS), a watch in the Codex/Kimi adapters.
