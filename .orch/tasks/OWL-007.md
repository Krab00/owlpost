## Description
Implement `client.rs` and `cli/ask.rs` per `docs/technical-design.md §9` and
`docs/architecture.md §3.1`. `client::send_question(book, identity, contact, envelope)` tries
each endpoint in order with a pinned reqwest client (connect timeout 2 s) and maps responses:
200 → verified answer, 202 → accepted id, 403 → Unavailable, 429 → RateLimited(retry_after),
connect errors on all endpoints → Offline. `owl ask <peer> <path> "<question>"`: resolve the
peer, determine `project` (`--project` or the normalised `origin` remote of the current git
repo, else the directory name), check the asker-side cache unless `--no-cache`, send, print the
answer or `accepted <id>` and write `asks/<id>.json`. `--wait <secs>` polls the peer's outbox
every 2 s until the answer arrives (verify, store in inbox, ack, cache) or the deadline passes
(exit 4). `owl ask --file <path> "<question>"` runs `git blame --line-porcelain` on the file,
aggregates author emails by line count, maps them through contact emails, and prints the top 3
as candidates (`--json` list; without `--json` an interactive numbered pick, or `--peer` to
skip). Exit codes per §9.

- [ ] AC7: integration test `tests/ask.rs::blame_candidates` creates a fixture repo with commits by two emails that match two contacts and one that matches none; `owl ask --file <f> "q" --json` lists the two contacts ordered by line share with their line counts (modality: test)
