## Description
The plugin ships five commands (`inbox`, `ask`, `history`, `me`, `update`); the rest of the
`owl` CLI (`whoami`, `card`, `contact`, `add`, `allow`, `deny`, `show`, `draft`, `edit`,
`send`, `reject`, `watch`, `install`, `uninstall`, `doctor`, `init`) is only available by
leaving the session for a terminal. Users expect `/owlpost:<anything owl can do>`
(requested 2026-09-05).

Add one `commands/<name>.md` per user-facing subcommand, each a thin wrapper: run the `owl`
command with `$ARGUMENTS`, show the output, and offer the natural next step (after `show`:
draft/send/reject; after `add`: allow; after `doctor` failures: the fix). Rules:

- `daemon` gets no command (it is a service; `install`/`uninstall`/`doctor` cover it).
- Commands that send something or change trust (`send`, `allow`, `deny`, `reject`,
  `uninstall`) confirm once with `AskUserQuestion` before running, like `ask` does today.
- `contact` becomes `/owlpost:contacts` (OWL-020 picker) plus `/owlpost:contact <show|export|remove> ...`.
- `allowed-tools` in each frontmatter is limited to the exact `owl <sub>:*` pattern.
- `plugins/claude-code/README.md` command table and `skills/owlpost/SKILL.md` list every
  command; `tests/plugin.rs::commands_have_descriptions` is driven by the directory listing
  instead of a hard-coded list, and a new test asserts that every `owl --help` subcommand
  except `daemon` has a matching `commands/<name>.md` (`contact` → `contacts.md` + `contact.md`).

Out of scope: new `owl` functionality; changing existing command semantics.
