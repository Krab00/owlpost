## Description
User request 2026-09-06: answering a question today takes two pickers — Draft on the
`pending` record, then Send on the `drafted` one. The user wants to decide once.

Add a **Draft & send** pick; keep Draft (two-step) for when the human wants to read first.

- **`commands/inbox.md` step 3** picker becomes **Draft / Draft & send / Reject / Skip**.
  `Draft & send`: run `owl draft <id>`, print the draft verbatim in a code block (as step 4
  does), then run `owl send <id>` at once, without a second picker. The pick is the human's
  explicit approval to send whatever the harness produced; say so in the option description
  (`sends the draft as-is; pick Draft to read it first`). On a non-zero `owl draft` exit show
  the error and stop (nothing is sent); on a non-zero `owl send` exit show the error, the
  record stays `drafted`.
- **`commands/draft.md`**: after showing the draft, the offer includes `/owlpost:send <id>`
  as today; additionally accept `--send` in its arguments (`/owlpost:draft <id> --send`) which
  does draft, print, send in one go, same rules. `--send` is stripped before `owl draft`
  is run (owl has no such flag).
- **Ground-rule wording.** SKILL.md "The answer loop" step 6 and the sentence `Never chain
  \`owl draft\` and \`owl send\` in one step` (skill, inbox.md, draft.md) become: `Never
  chain owl draft and owl send unless the human picked "Draft & send" (or passed --send);
  the draft is still printed in full before owl send runs.` The `consent` picker is
  unchanged (allow ≠ answer).
- Tests: `tests/plugin.rs` pins the new picker option name in inbox.md, the `--send`
  argument in draft.md, and the amended ground-rule sentence in all three files (stated
  three times → pinned three times); asserts the old absolute sentence is gone.

Out of scope: an "Allow & draft & send" pick on consent records; auto policy (that is
`owl allow --always`).
