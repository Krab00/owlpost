## Description
Implement `server.rs` and the listener half of `daemon.rs` per `docs/technical-design.md §7`
and `docs/architecture.md §3.2`. axum router served by axum-server with the OWL-005 rustls
config; a connection-level extension carries the peer fingerprint (or none for unpinned card
requests). Routes: `GET /.well-known/agent-card.json` and `/.well-known/agent.json` (A2A-shaped
card per §7, `owlpost.responds` derived from `config.responder.enabled`); `POST /v1/questions`
(verify body signature against the pinned peer key, schema check, replay window, per-peer token
bucket, policy lookup → 403 `unavailable` for `never` or responder disabled; no policy → store
inbox record with state `consent` and return 202 (an unconsented peer never receives a cached
answer); `manual`/`auto` → responder cache hit → 200 with the cached answer, else store inbox
record with state `pending` and return 202 — policy before cache, per architecture §3.2); `GET /v1/outbox` (answers whose `to` equals the caller);
`POST /v1/outbox/{id}/ack` (move to done; 404 if not the caller's). Every malformed input is a
4xx with an `error` field naming the problem. `owl daemon --foreground` runs the server on
`config.listen` (port 0 allowed for tests; the bound address is logged and written to
`$OWLPOST_HOME/daemon.addr`). Auto-accept scheduling and the pull loop are later tasks; leave
clearly named hooks for them.

- [ ] AC3: integration test `tests/server.rs::no_policy_means_consent` posts from a peer without a policy overlay and asserts the record state is `consent` (modality: test)
- [ ] AC4: integration test `tests/server.rs::never_and_disabled_return_unavailable` asserts 403 with `{"error":"unavailable"}` for a peer with mode never and for any peer when `responder.enabled == false`, and that no inbox record is created (modality: test)
- [ ] AC5: integration test `tests/server.rs::bad_inputs_are_4xx_never_500` covers: wrong signature (400), body signed by A but `from` claims C (400), stale ts (400), duplicate id (409), non-JSON body (400), missing `body.question` (400) — each response names the problem in `error` (modality: api)
- [ ] AC6: integration test `tests/server.rs::rate_limit_trips` with a contact `rate_limit_per_hour = 3` asserts the 4th question within a minute returns 429 with a `Retry-After` header (modality: test)
- [ ] AC7: integration test `tests/server.rs::cache_hit_returns_answer` pre-populates B's responder cache for the question hash and asserts the POST returns 200 with a verifiable answer envelope from B (modality: test)
- [ ] AC8: integration test `tests/server.rs::outbox_is_per_caller_and_ack_moves_to_done` puts answers addressed to A and to C in B's outbox; A's GET lists only its own; ack of A's id returns 204 and the record is in `done/`; ack of C's id by A returns 404 (modality: test)
- [ ] AC9: `owl --home <tmp> daemon --foreground` with `listen = 127.0.0.1:0` writes `daemon.addr` within 2 s and serves the card at that address (modality: test)
