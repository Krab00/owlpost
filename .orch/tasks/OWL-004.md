## Description
Implement `contacts/` per `docs/technical-design.md §5`. `repo.rs` finds the git root from the
current directory (walk up to a `.git`) and loads every `.agents/peers/*.json`; `local.rs` loads
`$OWLPOST_HOME/contacts/*.json`; `ContactBook::load(home, cwd)` merges them (repo data wins for
name/emails/endpoints, local file with the same pubkey contributes only `policy`). Implement
`resolve(query)` (fingerprint → email → unique name prefix; ambiguity error listing candidates),
`policy_for(fingerprint) -> Option<Policy>`, `set_policy(fingerprint, Policy)` writing the overlay.
CLI: `owl contact list` (table with name, fingerprint, source, policy mode), `owl contact show
<peer>`, `owl contact export` (this machine's repo entry built from config + key, JSON to stdout).
Malformed contact files are skipped with a warning on stderr, never a panic.

## Acceptance criteria
- [ ] AC1: integration test `tests/contacts.rs::repo_provider_finds_peers_from_subdir` creates a fixture git repo with two peer files, runs `ContactBook::load` from a nested subdirectory, and asserts both contacts with `source == "repo"` (modality: test)
- [ ] AC2: integration test `tests/contacts.rs::local_overlay_only_contributes_policy` writes a local file with the same pubkey as a repo contact but a different name and `policy.mode = "auto"`; asserts the merged contact keeps the repo name and has mode auto (modality: test)
- [ ] AC3: integration test `tests/contacts.rs::resolve_orders_and_ambiguity` asserts resolution by fingerprint, by email, by unique name prefix, and that a prefix matching two names errors with both names in the message (modality: test)
- [ ] AC4: integration test `tests/contacts.rs::malformed_file_is_skipped` places an invalid JSON file in `.agents/peers/` and asserts loading succeeds with the valid peers (modality: test)
- [ ] AC5: `owl --home <tmp> contact export` after `owl init` prints JSON with exactly the keys `name`, `emails`, `pubkey`, `endpoints` whose pubkey equals `owl whoami --json` pubkey (modality: test)
- [ ] AC6: `owl --home <tmp> contact list` run inside the fixture repo prints one row per merged contact including the policy column (modality: test)
