## Description
Asking from Claude Code today requires typing the peer's exact name prefix into
`/owlpost:ask <peer> <path> <question>`; a wrong spelling fails resolution
(`no contact matches "Krzysiek"`, observed 2026-09-05). Users want to type
`/owlpost:contacts`, see who they can ask, pick one and continue to the question without
retyping the name.

Claude Code slash commands cannot run their own TUI, but a command's prompt can drive the
`AskUserQuestion` tool, which Claude Code renders as a list navigated with the arrow keys and
confirmed with Enter (the same widget as permission prompts). That is the required UX: one
option per contact, arrows to move, Enter to pick, no typing of names. The prompt must: list the merged book (`owl contact list --json`), present one option
per contact (name, fingerprint short, scope, policy, reachability hint from
`owl doctor`-style probe if cheap), and after the pick continue with the `/owlpost:ask`
flow: optional path (OWL-018), question text, explicit confirmation, `owl ask`. Selecting
a contact without asking anything just prints its `owl contact show` card.

Ship it as `plugins/claude-code/commands/contacts.md`; reuse the ask flow by reference
(`commands/ask.md`), do not duplicate the confirmation rules. Update the skill
(`skills/owlpost/SKILL.md`) so "ask a peer" mentions `/owlpost:contacts` as the entry point
when the user does not name a peer.

Out of scope: a picker in the `owl` CLI itself, editing contacts from the picker (OWL-019
covers add/remove), notifications.
