## Description
Ship the one-command install per `docs/concept.md` (Rollout). GitHub Actions `release.yml`
triggered by a `v*` tag: builds `owl` for `aarch64-apple-darwin`, `x86_64-apple-darwin`,
`x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` (cargo-zigbuild or cross), attaches
tarballs plus `SHA256SUMS` to a GitHub release. `scripts/install.sh`: detects OS/arch,
downloads the latest release asset, verifies the checksum, installs to `~/.local/bin/owl`
(or `/usr/local/bin` with `--system`), prints next steps (`owl init`, `owl install`,
`owl contact export`). README quickstart: install → `owl init` → `owl install` → export the peer
file → PR into `.agents/peers/` → `owl doctor` → first `owl ask`. `docs/pilot.md`: onboarding
checklist for the 4–5 pilot users, the `CODEOWNERS` line and admin fingerprint-check procedure,
the metrics to collect (from `owl history --json`), and the kill criteria.

## Acceptance criteria
- [ ] AC1: `.github/workflows/release.yml` builds the four targets and uploads assets + `SHA256SUMS` on a `v*` tag; a dry run with `workflow_dispatch` on a branch produces the artifacts (modality: data)
- [ ] AC2: `scripts/install.sh --version <tag> --prefix <tmpdir>` on the development machine installs a working `owl` (`<tmpdir>/owl --version` prints the tag's version) and fails with a non-zero exit on a checksum mismatch (simulated by `OWL_INSTALL_FAKE_SUM=1`) (modality: test)
- [ ] AC3: `README.md` contains the quickstart steps in order: install, `owl init`, `owl install`, `owl contact export`, PR, `owl doctor`, `owl ask` (modality: data)
- [ ] AC4: `docs/pilot.md` exists with sections Onboarding, CODEOWNERS and fingerprint check, Metrics, Kill criteria (modality: data)
- [ ] AC5: `cargo test --workspace`, clippy and fmt pass on the release branch (modality: test)
