## Description
Implement `cli/allow.rs`, `cli/deny.rs` and the auto-accept scheduler in `daemon.rs` per
`docs/concept.md` (Trust) and `docs/architecture.md §3.2, §3.4`. `owl allow <peer> --once`
releases every held `consent` record from that peer to `pending` without writing a policy;
`owl allow <peer>` (default) writes policy `manual` and releases; `owl allow <peer> --always`
writes `auto` — for a `local`-source contact this requires `--i-verified-the-fingerprint`,
otherwise exit 1 with an explanation. `owl deny <peer>` writes `never` and moves held records
to `done/` (state `denied`). `owl inbox` renders consent records as a prompt line
(`<name> wants to ask your agent about <project> — owl allow <fp> [--once|--always] / owl deny <fp>`).
Daemon auto-accept: on each spool scan, for `pending` questions from peers with mode `auto`,
run the runner, redact, sign, send (same code path as `owl send`), append one JSON line to
`$OWLPOST_HOME/log/outgoing.jsonl` (`ts, to, question_id, harness, redactions, answer_sha256,
mode: "auto"`), and notify; failures (timeout, unknown project, extract_failed) leave the record
`pending` with an `auto_error` field so the human sees it in `owl inbox`. `owl send` in manual
mode also appends to the outgoing log with `mode: "manual"`.
