## Description
Observed 2026-09-06 23:08–23:15 UTC in an interactive session: the model walked `/owlpost:inbox`
and printed the consent question and the three answer records in its own layout (a plain bold
header, a table with a `🟢` marker and a `re:` column) instead of the SKILL.md "Framed message"
(16 × 🟧, `🦉 **<peer>** · HH:MM · <project> · <path>`) and "Showing messages" (`🟦 00:16 ·
<peer> | text`) formats. Root cause is structural: `commands/inbox.md` is what the model has in
context, and in four places it says "see the skill, 'Framed message'" / "see the owlpost skill,
'Showing messages'". SKILL.md is not loaded when the command runs, so the reference points at
text the model has never seen and it improvises. Any model, any harness, will do the same.

Fix: render in code, not in prose. The CLI prints the finished Markdown; the command says
"paste the output verbatim". One rule instead of a template to copy, deterministic, the same
for Claude, Codex and Kimi, and testable.

- `owl show <id> --format claude` prints the framed block for a `question` record (any
  state) and for an `answer` record: line 1 and the last line are exactly 16 × `🟧`; line 2 is
  `🦉 **<peer name>** · HH:MM · <project or `-`> · <path or `whole repository`>`; on a
  `consent` record the header carries the fingerprint after the name (`**<name>** (owl:…)`);
  the body is the message text verbatim inside a ```` ```text ```` fence (a text containing
  three backticks is fenced with four). HH:MM is the local time of `received_at`. A `drafted`
  record prints the frame for the question, then `draft:` and the draft in a plain
  ```` ```text ```` block (drafts are ours, never framed), then `harness: <name>`. When the
  draft's language differs from the question's (detected by a small stopword heuristic,
  Polish/English only; ponytail), one line `note: the draft is in a different language than the
  question — pick Edit` follows. Without `--format` the plain output is unchanged.
- `owl inbox --format claude` (listing mode, no `--count`) prints the received-messages table
  for the `answer` records: header-less two-column Markdown table, newest last, only records
  received in the last 24 h, at most the 10 newest, one line under it `<N> older answers not
  shown — owl history` when any were cut; the left cell is `<marker> HH:MM · <peer name>`, the
  right cell the answer text verbatim with `|` escaped as `\|` and newlines as `<br>`; above the
  table one line per answer `↳ <question id short> "<first line of the question, ≤60 chars>"`
  keyed by the same marker, so each answer names the question it replies to. Markers come from
  the fixed list 🟦 🟩 🟨 🟪 🟧 🟥 (then repeat) and are assigned per peer fingerprint in order
  of first appearance, persisted in `$OWLPOST_HOME/markers.json` (append-only map fingerprint →
  index), so the same peer keeps the same marker across calls and sessions. Question records in
  the listing are printed as framed blocks (same renderer as `owl show`), consent ones first.
  Listing still marks the listed records seen. `--format codex|kimi` in listing mode print the
  same Markdown (the harness-specific difference is only in `--count` injection lines).
- `plugins/claude-code/commands/inbox.md`: every "print the framed message block (see the
  skill …)" becomes `run owl show <id> --format claude and paste its output verbatim`; the
  answers step becomes `run owl inbox --format claude and paste its output verbatim`; no
  sentence in the file refers the reader to another file for a format. A "Never" list at the
  top: never a Markdown table for a single question; never your own icons, markers or columns;
  never paraphrase; the orange frame always means "from a peer". SKILL.md "Showing messages" and
  "Framed message" keep the examples but state that the CLI renders them and the model pastes.
- Design doc §9 (CLI contract): the `--format claude` output of `show` and `inbox` listing,
  the frame literals, the 24 h / 10 rows rule, `markers.json`.

Out of scope: colours in the terminal (plain output unchanged), the history command's rendering
(`owl history --format claude` can reuse the table renderer later), any change to `--count`
injection lines (OWL-031 contract stays byte-identical).
