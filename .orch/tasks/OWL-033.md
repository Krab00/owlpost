## Description
OWL-031 registers `watchPaths` in every interactive session at SessionStart, so with 3–4 open
Claude sessions one inbox record wakes all of them and every one of them runs `/owlpost:inbox`
and asks the human the same consent/draft question. Wanted: exactly one session wakes and asks;
the others stay silent; if that session does not handle the record within a lease, the record
is up for grabs again; when no session is alive the record simply waits for the next
SessionStart (today's fallback path, unchanged).

Design: a claim per record, taken inside the FileChanged hook, with affinity for the session
whose checkout the question is about. No "owner session" for the whole watch (the owner may sit
in another repo or be busy for hours).

- `owl inbox --count --format claude --hook-event FileChanged` on `event: add` derives the
  record id from the hook's `file_path` (`<id>.json`), reads `session_id` and `cwd` from the
  hook stdin, then tries to claim: create `$OWLPOST_HOME/spool/claims/<id>` with `O_EXCL`
  holding `{"session_id","cwd","claimed_at"}`. Success → today's wake (sentence on stderr,
  exit 2). `EEXIST` with a live claim → exit 0, silent. An existing claim is dead when
  `claimed_at` is older than `OWLPOST_CLAIM_TTL_SECS` (default 600): it is removed and the
  create is retried once (the race between two removers is benign: one `O_EXCL` wins).
- Affinity without coordination: when the canonicalised `cwd` equals the configured checkout
  of the record's `project` (`config.projects`), the hook claims immediately; otherwise it
  sleeps `OWLPOST_CLAIM_DELAY_MS` (default 1000, well inside the hook's 5 s timeout) before
  claiming. A record without a project mapping is claimed immediately by everyone (first wins).
  Records that are not questions (`answer`) are claimed the same way — one session shows the
  answer.
- Release: `owl show`, `owl draft`, `owl edit`, `owl send`, `owl reject` on the record and
  `owl inbox` listing (which marks seen: a human has looked at it in some session) remove the
  claim. `--hook-event SessionStart` sweeps `spool/claims/`: entries whose record is no longer
  in `inbox/` or whose lease expired are removed (best effort, never fails the hook).
- Session liveness is not consulted (the hook does not learn the session's pid). Ponytail: a
  dead session holds its claim for at most one TTL; the SessionStart/UserPromptSubmit counter
  line still shows the record in every session, so nothing is hidden, only the wake is
  suppressed. Upgrade path: map `session_id` → pid through `~/.claude/sessions/*.json` when
  that file format is documented.
- `SessionStart`, `UserPromptSubmit`, `PostToolUse` injection lines are unchanged (pull,
  informational, per session).
- `scripts/e2e-watch-claim.sh`: two headless `claude -p --input-format stream-json` sessions
  with the installed/`E2E_PLUGIN_DIR` plugin, one record dropped after both printed their first
  `result`; asserts exactly one stream carries a `FileChanged` `hook_response` with
  `exit_code` 2 and a second `assistant` event, the other carries `exit_code` 0 and no second
  turn; prints `PASS`/`FAIL`. Built on `scripts/e2e-watch-wake.sh` (which stays).
- Design doc §8 (spool: `claims/` dir, lease, release points), §9 (`FileChanged` claim
  semantics, the two env knobs), §12 (the new script).

Out of scope: choosing between two sessions in the same checkout (first `O_EXCL` wins),
cross-machine claims, any change to the daemon.

## Acceptance criteria
- [ ] AC1: with one unseen record `<id>.json` in `inbox/`, two `--hook-event FileChanged` runs with stdin `{"session_id":"A","cwd":"<tmp>/x","file_path":"…/<id>.json","event":"add"}` and the same with `B` (run sequentially, `OWLPOST_CLAIM_DELAY_MS=0`): the first exits 2 with the sentence on stderr, the second exits 0 with no output; `spool/claims/<id>` holds `session_id` `A`; the count is unchanged (nothing seen) (modality: test)
- [ ] AC2: affinity: `config.projects` maps the record's project to `<tmp>/repo`; run the hook for session `B` with `cwd` `<tmp>/other` and `OWLPOST_CLAIM_DELAY_MS=400` in the background, 50 ms later run it for session `A` with `cwd` `<tmp>/repo`: `A` exits 2, `B` exits 0, the claim names `A`; with no mapping for the project both claim immediately and exactly one exits 2 (modality: test)
- [ ] AC3: lease: a claim file with `claimed_at` older than `OWLPOST_CLAIM_TTL_SECS=1` is replaced and the new hook run exits 2; a claim younger than the TTL is respected (exit 0) (modality: test)
