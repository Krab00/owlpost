## Description
OWL-031 registers `watchPaths: [spool/inbox]` in every interactive session, so with 3–4 open
Claude sessions one record wakes all of them and each one runs `/owlpost:inbox` and asks the
human the same question. Goal: exactly one session wakes and asks; the others stay silent; if
that session does not handle the record within a lease, the record moves to the next session;
when no session is alive the record waits for the next SessionStart (today's fallback path).

Rejected alternative (first draft of this task): a claim race in the FileChanged hook
(`O_EXCL` on `spool/claims/<id>`, non-affine sessions sleep before claiming). It needs N hooks
racing with sleeps, cannot tell a dead session from a slow one, and hands over only on the next
event. The variant below has one decision point with full information.

Design: **a private wake directory per session, routing done once by the daemon.**

Verified on this machine (claude 2.1.263, 2026-09-06 23:14–23:50 UTC) before writing this:
every hook's stdin carries `session_id`, `cwd`, `transcript_path`; FileChanged adds `file_path`
and `event`; `SessionStart` fires with `source` ∈ startup/resume/clear/compact/fork;
`SessionEnd` exists; the watch list is per process (matchers + hook-returned `watchPaths`,
chokidar with `awaitWriteFinish` 500 ms, so tmp+rename is exactly one `add`); an
`asyncRewake` exit 2 wakes an idle session in ~7 s and, when the session is busy, is queued and
delivered right after the running tool call (planted record at 23:45:42 during a 9 s command,
delivered at 23:45:52, nothing lost); `~/.claude/sessions/<pid>.json` maps `sessionId` → `pid`
(internal format, used only as a liveness hint).

Layout under `$OWLPOST_HOME`:
```
sessions/<session_id>/marker.json   {session_id, cwd, started_at, heartbeat_at, source}
sessions/<session_id>/wake/<record_id>.md   the text the hook prints (watched dir)
sessions/<session_id>/tmp/          staging for atomic rename into wake/
spool/routing/<record_id>.json      {current: <session_id>|null, routed_at, tried: [..]}
```
`marker.json` lives outside `wake/` so heartbeat writes never produce FileChanged events.

Plugin side (`hooks/owl-count.sh` stays the single entry point; `hooks.json` gains a
`SessionEnd` entry `owl-count.sh --hook-event SessionEnd`, timeout 5):
- `SessionStart`: `owl inbox --count --format claude --hook-event SessionStart` creates
  `sessions/<sid>/{wake,tmp}`, writes `marker.json` from stdin (`session_id`, canonicalised
  `cwd`, `source`), returns `watchPaths: ["<home>/sessions/<sid>/wake"]` (no longer
  `spool/inbox`), then assigns the backlog: every unseen inbox record whose routing has no
  live `current` gets `current = <sid>` (no wake file — the `additionalContext` previews and
  `owlpost: run /owlpost:inbox now.` already surface the backlog at start, and the watcher is not
  armed yet). Sweeps `sessions/`: markers that are dead (below) are removed with their dirs.
- `UserPromptSubmit`, `PostToolUse`: as today plus a heartbeat (`heartbeat_at` in
  `marker.json`, written atomically); never fail the hook.
- `SessionEnd`: removes `sessions/<sid>/` and clears `current` in every routing that names
  `<sid>`; exit 0 always.
- `FileChanged`: on `event: add` with `file_path` under `<home>/sessions/<sid>/wake/` and the
  watch enabled, prints the file's content on stderr and exits 2; every other case exits 0
  silently (`change`, `unlink`, other paths, `{"watch": false}`, unusable stdin).

Wake file content: the `owl show <id> --format claude` block when OWL-032 is merged; until
then the OWL-031 counter sentence followed by `owlpost: run /owlpost:inbox now.` — the hook
never composes text, it prints the file.

Routing (`src/route.rs`, one module used by the daemon and by the CLI):
- `route(home, config, record_id)`: candidates = live markers; order: (1) `cwd` equals the
  configured checkout of the record's `project` (`config.projects`, canonicalised; a record
  without a mapping skips this rule), (2) newest `heartbeat_at`; excludes sessions in
  `tried`. Writes the wake file via `tmp/` + rename, records `current`, `routed_at`, appends to
  `tried`. No candidate → `current = null`, nothing written (the next SessionStart picks it up).
- Live marker: `marker.json` exists, and when `~/.claude/sessions/*.json` names its
  `sessionId` the pid is alive (`/proc/<pid>`), and `heartbeat_at` is younger than
  `OWLPOST_SESSION_STALE_SECS` (default 21600). A marker whose sessions file names a dead pid
  is dead regardless of heartbeat. `// ponytail:` on the sessions-file lookup (internal Claude
  Code format; the hook does not receive the pid).
- Called from the daemon right after `spool.put(Dir::Inbox, …)` in `server.rs` (incoming
  question) and `pull.rs` (pulled answer) — the only two places a new inbox record is born;
  `owl route <id>` exposes the same call for scripts and the e2e test (no daemon needed).
- Lease loop in the daemon (`daemon.rs`, next to the auto scheduler), every 30 s: for every
  routing with `current` set, `routed_at` older than `OWLPOST_WAKE_LEASE_SECS` (default 600)
  and the record still in `inbox/` with `seen == false`: remove that session's wake file and
  route again (the session goes to `tried`). A record that was seen stays where it is: a human
  looked at it. A `current` whose marker died is re-routed at once on the next tick.
- Release: `owl show`, `owl draft`, `owl edit`, `owl send`, `owl reject` on the record and
  `owl inbox` listing (marks seen) remove `sessions/*/wake/<id>.md` and `spool/routing/<id>.json`
  (best effort, never fail the command). Moving a record to `done/` removes them too.
- Design doc §8 (routing state, wake dirs, lease, release points), §9 (`FileChanged` prints the
  wake file; `owl route`; the two env knobs; `SessionEnd`), §11 (daemon lease loop), §12
  (`scripts/e2e-watch-route.sh`).
- `scripts/e2e-watch-route.sh`: two headless `claude -p --input-format stream-json` sessions
  with the plugin (`E2E_PLUGIN_DIR` or the installed one), each with a distinct temp cwd, one of
  them the configured checkout of the test project; after both printed their first `result`,
  drop a record into `spool/inbox` and run `owl route <id>`; assert the affine session's stream
  carries a `FileChanged` `hook_response` with `exit_code` 2 and a second `assistant` event, the
  other stream carries no FileChanged response and no second turn; prints `PASS`/`FAIL`.
  `scripts/e2e-watch-wake.sh` is updated to route explicitly (`owl route`) after dropping the
  record, otherwise unchanged.
- Nice to have, not a criterion: `hooks.json` `rewakeSummary: "🦉 owlpost"` on the FileChanged
  entry (replaces "Stop hook feedback" in the terminal; the field is marked `@internal` in
  Claude Code's schema, so it is added only if the schema accepts it without a warning).

Out of scope: two sessions in the same checkout (rule 2 decides, ties by heartbeat), machines
other than this one, changes to the auto scheduler, the wake file's rendering (OWL-032).
