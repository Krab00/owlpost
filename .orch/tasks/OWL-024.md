## Description
Finding from the 2026-09-05 session: the `/owlpost:contacts` picker cannot work everywhere.
Claude Code's Bash tool has no terminal, so a real arrow-key list needs a tmux pane or a
desktop window (neither exists over SSH), and `AskUserQuestion` caps at 4 options, which
does not scale to a book of 250 contacts. The user asked for the same typeahead Claude Code
already has for `@` file mentions.

Claude Code lists **MCP resources** in the `@` autocomplete next to files, fuzzy-searched on
the resource path, and attaches the resource content to the prompt automatically
(code.claude.com/docs/en/mcp "Use MCP resources"). Plugins may bundle an MCP server via
`.mcp.json` at the plugin root. So the contact book becomes a resource server:

- **`owl mcp`** — an MCP server over stdio (JSON-RPC 2.0, one JSON object per line, no
  new crates: `serde_json` + std I/O). It exposes **resources only**, no tools, so it costs
  nothing in the model context. One resource per contact of the merged book
  (`ContactBook::load(home, cwd)`): URI `to://<name-slug>.<email>` where `<name-slug>` is the
  name lower-cased with every run of non-alphanumerics replaced by `-` (trimmed) and
  `<email>` is the contact's first e-mail (a contact without e-mail gets `to://<name-slug>`);
  on a URI collision the fingerprint (without the `owl:` prefix, or its first 8 chars)
  is appended as another `.<segment>` so every URI is unique. `name` = the contact's name,
  `description` = `<fingerprint> · <source>`, `mimeType` = `application/json`.
  `resources/read` returns one text content: the JSON object `{"name","fingerprint","emails"}`
  (nothing else — the public key and endpoints are not needed to ask). Methods:
  `initialize` (echo the client's `protocolVersion`, capabilities `{resources: {}}`,
  serverInfo name `owl`, version = crate version), `notifications/initialized` (no reply),
  `ping` → `{}`, `resources/list`, `resources/read`, `resources/templates/list`,
  `tools/list` and `prompts/list` → empty lists; unknown method → error `-32601`; unknown
  URI → error `-32002` "resource not found"; a line that is not valid JSON-RPC → error
  `-32700`/`-32600` with `id: null`. Requests may arrive in any order; the server exits 0 on
  EOF. Contacts are re-read from disk on every `resources/list` and `resources/read` so a
  contact added mid-session shows up without a restart (whether Claude Code refreshes its
  menu is a PM-REVIEW question, not a criterion).
- **`plugins/claude-code/.mcp.json`**: `{"mcpServers": {"owl": {"type": "stdio",
  "command": "owl", "args": ["mcp"]}}}` — server name `owl`, so a mention reads
  `@owl:to://ana-kowalska.ana@acme.pl`.
- **Skill** (`skills/owlpost/SKILL.md`): a section "Mentioned contact" — an attached
  `to://` resource of the `owl` server in the user's prompt is the peer: the rest of the
  prompt is `[path] <question>`, run `owl ask --peer <fingerprint>` (with `--file <path>`
  when a path is given) at once, the mention is the approval; report who it went to (name
  and fingerprint), the path or "whole repository", and the result; several mentions send
  the same question to each. Also the rule already agreed today: an `/owlpost:ask` the user
  typed, or "ask Maciek why this retries" in their own words, is the approval — no
  confirmation step; only when Claude itself proposes asking a peer does it show peer,
  path and question first and wait for a yes. `/owlpost:send`, `allow`, `deny`, `reject`,
  `uninstall` keep their confirmation.
- **`commands/ask.md`**: same no-confirmation rule (resolve the peer, run at once, report
  in one line), `<peer>` stays required; the prior WIP wording is in
  `/tmp/claude-1000/-home-kris-Documents-owlpost/c7b31a0d-35e7-4175-a6c4-584973431dbf/scratchpad/picker-wip.patch`
  (ask.md and SKILL.md hunks; ignore every picker hunk there).
- **`commands/contacts.md`**: no picker of any kind. It runs `owl contact list --json`,
  prints the book as one table (name, e-mails, fingerprint, source, policy or `-`), and
  ends with the one-line hint that a contact is asked by mentioning it:
  `Type @ and the contact's name, e.g. @owl:to://<first contact's uri>, then the question.`
  Empty book: "No contacts yet — run /owlpost:add with a colleague's peer file." and stop.
  `allowed-tools` = `Bash(owl contact:*)` only. No `AskUserQuestion`, no `owl ask`.
- **README** (`plugins/claude-code/README.md`): the `/owlpost:contacts` and `/owlpost:ask`
  rows updated, one new paragraph "Mention a contact" with the `@owl:to://…` example and
  the note that `.mcp.json` starts `owl mcp` (needs `owl` on PATH, like the hooks).
- **Design doc** `docs/technical-design.md` §9: a CLI table row for `owl mcp`; §2 module
  layout gains `cli/mcp.rs`.

Out of scope: MCP tools or prompts, a `#` or custom trigger character (Claude Code has none
for plugins), Codex/Kimi adapters, watching the book for changes (`listChanged`).
