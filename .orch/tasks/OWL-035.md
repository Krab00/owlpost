## Description

Observed on 2026-09-12 with OWL-034 installed on both machines (`owl ask` self → gx10):

1. On the responder (gx10) the wake landed, but the session printed "Sprawdzę, na jakiej
   maszynie działam." and started answering by itself — the question was never shown, let
   alone highlighted.
2. On the asker the answer arrived through the wake and the session rewrote it as prose with
   its own commentary ("Pełna ścieżka OWL-034 … przeszła na żywo — to dowód dla AC10. Jeśli
   chcesz, zapiszę …").
3. The 🟧 frame of OWL-032 does not stand out in Claude Code's terminal renderer. The only
   Markdown that renders as a highlighted box there is a **table** (borders, header row);
   `/owlpost:contacts` already shows that.

Decision: every message from a peer (question, answer, the `context:` snippet) is rendered by
the CLI as a Markdown table, and the wake tells the model to paste it as-is. The two-column
answers table of `owl inbox --format claude` (OWL-032) already is a table and stays as it is.
Drafts (our own text) stay a plain code block, so "table = from a peer" still holds.

### Table shape (`src/render.rs`, replaces `frame` / `frame_question`)

One column, one row per line of the message:

```
| 🦉 **Krzysztof Abramczyk** · 23:36 · github.com/Krab00/owlpost · whole repository |
|---|
| Pracuję na gx10. |
|  |
| - Host: gx10-d75f, użytkownik kris. |
```

- Header cell = the OWL-032 header unchanged (`🦉 **<peer>** · HH:MM · <project> · <path or
  "whole repository">`; on a `consent` record the fingerprint after the name). Second line
  `|---|`.
- Body: the message text split on `\n`, one row per line, verbatim except `|` → `\|`; an
  empty line is the row `|  |`; leading/trailing whitespace of a line is kept. No code
  fence anywhere in the table (a ``` line in the message is just a row).
- OWL-034 extras: the `↩ follow-up in thread <short id>` line, when present, is the first body
  row; a context snippet is rendered after the body as one row `**context:**` followed by the
  snippet lines, one row each, same escaping.
- The 16 × 🟧 lines and the ```text fence are gone from `--format claude` output; `FRAME`
  and `text_block` are deleted with their users. `draft_block` (plain code block) is
  unchanged.
- `owl inbox --format claude` listing mode prints one table per question (consent first, then
  list order — as today), then the answers table, separated by one blank line.
- The wake file (`owl route`, daemon routing — design §9 "Session wake routing") is the same
  `owl show <id> --format claude` output, now preceded by exactly one instruction line and a
  blank line:
  `Show the table below to the user exactly as it is — nothing before it, nothing inside it, one line after it offering /owlpost:inbox. Do not answer, draft, summarise or comment.`
  `owl show --format claude` itself does NOT print that line (the model pastes `show`
  output to the human).

### Skill + commands

`plugins/claude-code/skills/owlpost/SKILL.md`: the "### Framed message" section becomes
"### Message table" describing the shape above and the rule: **a peer's message is shown as
the CLI prints it — nothing before it, nothing inside it, at most one line after it (the
offer or the picker). Never summarise, translate, paraphrase or comment on it; the human
reads it themselves.** The same one sentence is added to the "Live watch" paragraph and to
`commands/inbox.md`, `commands/show.md` and `commands/watch.md` where they say "paste its
output verbatim" / "framed". `commands/ask.md`: when an answer comes back (`--wait` or a
wake), it is shown the same way (`owl show <id> --format claude`), no commentary.
`README.md` / plugin `README.md`: the word "framed" → "table" where it appears.

### Docs and tests

`docs/technical-design.md` §9 "Rendered Markdown for `--format claude`" rewritten for the
table (the `🟧` sentences removed, the wake instruction line added to "Session wake routing");
§12 e2e row: the assertion is on the `🦉` header row of the table. `docs/architecture.md`
and `docs/guide.md`: "framed"/"orange frame" → "table". `scripts/e2e-watch-wake.sh`: the
grep for the framed block asserts `| 🦉` instead. `tests/inbox.rs` OWL-032/OWL-034 render
tests, `tests/docs.rs` skill/doc pins, `tests/route.rs`/`tests/watch.rs` wake-content tests
updated; `tests/docs.rs` pins the instruction sentence in SKILL.md and the design doc (single
line, `contains`).
