## Description
Finding from the second cross-machine test (2026-09-05): `owl ask` and `/owlpost:ask` require a
`<path>`, so a question about the repository as a whole ("how long is your README?", "which
branch do you deploy from?") has to be pinned to an arbitrary file. The path exists to seed the
responder's context and to let `--file` propose peers from `git blame`; it should not be a
precondition for asking at all.

Make the path optional end to end: `owl ask <peer> "<question>"` is valid, the envelope carries
`path: null` (or omits it), the responder's read-only session starts from the repo root with no
file hint, `owl inbox` / `owl history` / `owl show` print `-` where the path would be, and the
question hash covers the empty path so the dedup rule still holds. `--file` keeps its meaning
(peer proposal from blame + path). The plugin command `commands/ask.md` parses
`<peer> [path] <question...>` and no longer asks for a missing path.
